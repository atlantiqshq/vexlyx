# F5.17 Two-Factor Auth (TOTP) — Design Spec

> Date: 2026-09-25
> Status: approved design, awaiting spec review
> Decisions: optional per-user + `REQUIRE_ADMIN_2FA` enforce flag; recovery = backup codes + ADMIN reset

## 1. Problem

Auth today is password-only: `AuthService.login()` verifies argon2id and `createSession()` issues a Redis session immediately (`apps/api/src/modules/auth/routes.ts:66-86`, `apps/api/src/plugins/auth.ts:156-192`). `User` has no 2FA columns (`apps/api/prisma/schema.prisma:159-201`). An ADMIN credential leak gives unrestricted access (firewall, backups). Plesk/cPanel/CapRover all ship 2FA; Vexlyx has none.

## 2. Goal / Non-goals

Goal: TOTP second factor (authenticator-app compatible) layered on existing sessions.
Non-goals: WebAuthn/passkeys, SMS codes, changing session mechanics, transactional email (F5.23).

## 3. Architecture

New `twoFactor` service inside existing `auth` module (follow `routes.ts` → `service.ts` → `schema.ts` pattern). No new top-level module — it shares login/session code.

- TOTP lib: `otplib` (verify with ±1 step clock window). QR: `qrcode` (data-URL PNG). Both require explicit user sign-off per CLAUDE.md §6 — no install until plan approval.
- Secret at rest: encrypt via existing `apps/api/src/utils/encryption.ts` (AES-256-GCM). Recovery codes: argon2-hashed, single-use.
- Pre-2FA challenge: short-lived Redis key `2fa-challenge:<token>` (5-min TTL, `{ userId }`) — never a session cookie until TOTP passes.

## 4. Data model (Prisma migration)

```prisma
// add to User
totpSecretEncrypted String? @map("totp_secret_encrypted")
totpEnabled         Boolean  @default(false) @map("totp_enabled")
totpVerifiedAt      DateTime? @map("totp_verified_at")

// new model
model RecoveryCode {
  id        String   @id @default(cuid())
  userId    String   @map("user_id")
  codeHash  String   @map("code_hash")
  usedAt    DateTime? @map("used_at")
  createdAt DateTime @default(now()) @map("created_at")
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@index([userId])
  @@map("recovery_codes")
}
```

Generate 10 codes at setup, show once, hash before store.

## 5. API

| Method | Route | Auth | Behaviour |
|---|---|---|---|
| POST | `/api/auth/login` (modified) | public, 5/15min | password ok + `totpEnabled` → `202 { requires2FA: true, challengeToken }`, no cookie; else session as today. If `REQUIRE_ADMIN_2FA=true` and role is ADMIN without 2FA, return `403 ADMIN_2FA_REQUIRED` with setup hint. |
| POST | `/api/auth/2fa/challenge` | public, 5/15min | `{ challengeToken, code }` — code is TOTP or unused recovery code (marked used). Success → `createSession()`. Failure → 401, no session. |
| POST | `/api/auth/2fa/setup` | `requireAuth` | generate secret, encrypt + store (enabled=false), return `{ otpauthUrl, qrDataUrl, manualKey }`. Regenerating replaces pending secret. |
| POST | `/api/auth/2fa/verify-setup` | `requireAuth` | `{ code }` valid → `totpEnabled=true`, `totpVerifiedAt=now`, return `{ recoveryCodes: string[] }` once. Audit-log `2FA_ENABLED`. |
| POST | `/api/auth/2fa/disable` | `requireAuth` | requires `{ password, codeOrRecovery }` → clear secret, delete codes, `totpEnabled=false`. Audit-log `2FA_DISABLED`. |
| POST | `/api/users/:id/2fa/reset` | ADMIN | clears secret + codes, forces `totpEnabled=false`. Audit-log `2FA_ADMIN_RESET` with actor. Blocked for self-reset confusion: allowed, but logged. |
| GET | `/api/auth/config` (extended) | public | add `requireAdmin2FA: boolean` from env. |

Errors use existing shape `{ error, code, details }`. New codes: `2FA_REQUIRED`, `2FA_INVALID_CODE`, `2FA_ALREADY_ENABLED`, `ADMIN_2FA_REQUIRED`.

Env: `REQUIRE_ADMIN_2FA=false` in `apps/api/src/config/env.ts` + `.env.example` (per CLAUDE.md §14 process).

## 6. Frontend

- `LoginForm`: two-step — password form → if `requires2FA`, 6-digit code form (TOTP or recovery). No dashboard redirect until session exists.
- `/settings` Security card: status, Setup dialog (QR + manual key + verify input), recovery-codes display (copy, shown once), Disable (password + code confirm).
- `/users` edit dialog: "Reset 2FA" button (ADMIN only) with destructive confirm.
- Reuse `useRefreshAnimation` conventions; no new UI lib (render QR from data-URL `<img>`).

## 7. Security

- Rate-limit `challenge` + `verify-setup` at login tier (5/15min/IP).
- Challenge tokens: 32 random bytes, single-use, 5-min TTL, deleted on success/failure-exhaustion.
- Never log secrets/codes; `PUBLIC_USER_SELECT` unchanged (no secret leaks via `/me`).
- Recovery codes: 10 × 10-char alphanumeric, argon2 hash, constant-time compare via verify, invalidate after one use.
- Audit log (F5.18 `AuditLog`): `2FA_ENABLED`, `2FA_DISABLED`, `2FA_ADMIN_RESET` with actor/target, no secret material in metadata.

## 8. Testing

Per CLAUDE.md (happy + error + auth):
1. Enable → login requires code; valid TOTP → session; `/me` works.
2. Wrong/expired code → 401, no cookie; reused recovery code → 401.
3. No-2FA user → login unchanged.
4. `REQUIRE_ADMIN_2FA=true` → ADMIN without 2FA blocked at login with `ADMIN_2FA_REQUIRED`.
5. ADMIN reset → target's 2FA cleared, audit entry attributed to admin.

Manual: two authenticator apps (Google Authenticator + 1Password) + QR/manual-key paths.

- Placeholders: none — lib names, TTLs, table/column names, env name all concrete.
- Consistency: challenge-before-session matches "no session until TOTP passes"; audit actions match F5.18 pattern; rate limits match login tier.
- Scope: single plan, no WebAuthn/SMS/email. `REQUIRE_ADMIN_2FA` is env-only (no per-user enforce UI) — deliberate, matches approved answer.
